# QA Validation Prompt — Profile Settings + Avatar Pan/Zoom Cropper

## Summary
Pilots now have a settings page (`/settings`) to edit their handle, display name,
bio, and the default privacy for new flights, plus upload a profile avatar. The
avatar upload now opens an interactive **pan & zoom cropper** (circular mask) so
the pilot chooses exactly what shows in the avatar circle. Avatars surface in the
app header, the public profile, and settings, with an initials fallback. New flight
uploads now inherit the owner's chosen default visibility.

## Changes Overview

**Settings (`/settings`, owner-only):**
- Edit **handle** (3–20 chars, `[A-Za-z0-9_]`), **display name** (≤60), **bio** (≤280).
- **Default privacy** radios (Private / Public) for new flights.
- Handle uniqueness enforced — taking another pilot's handle is rejected with a message.
- Saving a new handle changes the public profile URL (`/@handle`).

**Avatar upload + cropper:**
- `/settings` avatar uploader: drag-drop or click to pick a JPEG/PNG/WebP/HEIC.
- For renderable images (JPEG/PNG/WebP) a **"Position your photo"** modal opens:
  drag to pan, scroll wheel or a zoom slider to zoom, inside a circular guide.
  Buttons: **Cancel** / **Save photo**. Escape cancels.
- **HEIC/HEIF** skips the cropper (browsers can't preview it) and uploads directly
  (server smart center-crop).
- On save, the chosen region becomes the avatar; the uploaded image is squared,
  re-encoded to 512² (full) and 128² (thumb) JPEGs, EXIF stripped.
- **Remove photo** clears the avatar back to the initials fallback.

**Avatar serving & surfaces:**
- Public serve by handle: `GET /api/profiles/[handle]/avatar?variant=full|thumb&v=<ts>`.
- Owner-only: `POST /api/profile/avatar` (multipart `file`, optional `crop` JSON),
  `DELETE /api/profile/avatar`.
- Avatar shown in the app header (links to `/settings`), the public profile
  (`/@handle`, full size), and the settings uploader. Initials shown when no avatar.

**Ingestion:**
- New flight uploads now inherit `Profile.defaultVisibility` (previously hard-coded
  private).

## Validation Scenarios

### Settings form (`/settings`)

**E2E scenarios:**
- **Edit display name + bio**: change both, Save, confirm "Saved." appears and the
  values persist after a page reload. Route: `/settings`.
- **Change handle updates profile URL**: change the handle, Save, then visit
  `/@<new-handle>` (should load) and `/@<old-handle>` (should 404 / not found).
- **Duplicate handle rejected**: with two pilots seeded, try to set pilot A's handle
  to pilot B's existing handle → expect the inline error
  "That handle is already taken — try another." and no change persisted.
- **Handle client validation**: input enforces `pattern="[A-Za-z0-9_]{3,20}"` — a
  2-char or symbol-containing handle should be blocked by the form.
- **Default privacy radios**: select Public, Save, reload → Public stays selected.
  Then upload a flight and confirm it lands **Public** (see ingestion check below).
- **Owner-only access**: `/settings` while signed out should redirect to sign-in
  (not render the form).

### Avatar cropper (the headline feature)

**E2E scenarios:**
- **Cropper opens for JPEG/PNG**: on `/settings`, choose a JPEG via the file input
  → a modal titled **"Position your photo"** appears containing the image inside a
  circular guide, a Zoom slider, and Cancel / Save photo buttons.
- **Image is visible in the modal** (regression guard): after picking the file, the
  photo actually renders inside the circle (it must not be blank). *Note: a prior
  bug left the blob URL revoked under React StrictMode — this scenario specifically
  guards that the `<img>` shows pixels.*
- **Zoom slider changes scale**: drag the Zoom slider toward max and confirm the
  image visibly enlarges within the viewport (the crop tightens).
- **Pan via drag**: drag the image inside the viewport and confirm it repositions
  (and is clamped so the circle never shows empty/background gaps at min zoom).
- **Save produces a cropped avatar**: pick → optionally pan/zoom → **Save photo** →
  modal closes, busy state shows, and the avatar in the uploader + header updates to
  the new image (the `?v=` cache-bust timestamp changes). Route: `/settings`.
- **Cancel discards**: open cropper → **Cancel** (and separately, **Escape**) → modal
  closes, no upload occurs, existing avatar (or initials) unchanged, and the same
  file can be re-selected afterward (file input resets).
- **Remove photo**: with an avatar set, click **Remove photo** → avatar reverts to
  the initials fallback across header, settings, and `/@handle`.
- **HEIC bypasses cropper**: choose a `.heic` file → **no** "Position your photo"
  modal appears; it uploads directly and (if decode succeeds) an avatar appears.
  *(If a real HEIC fixture is impractical in CI, assert the negative: the modal does
  not open for a `.heic`-named file.)*

**Vitest scenarios:**
- `processAvatar(bytes, mime, filename, crop?)` in `lib/avatar/process.ts`
  (already has tests in `lib/avatar/process.test.ts` — extend if useful):
  - With a `crop` of `{x,y,w,h}` fractions, output is 512² + 128² JPEG and EXIF-free.
  - An out-of-bounds crop (e.g. `{x:0.9,y:0.9,w:0.5,h:0.5}`) is clamped, not thrown.
  - No `crop` → falls back to attention center-crop (existing behavior).
- `normalizeHandle` / `normalizeDisplayName` in `lib/handle.ts`: valid handles pass
  and normalize (lowercasing); too-short/invalid-char/empty inputs return `{error}`.

### Avatar serving (`/api/profiles/[handle]/avatar`)

**E2E / request-level scenarios:**
- **Public serve by handle**: after a pilot uploads an avatar, `GET
  /api/profiles/<handle>/avatar?variant=full` returns `200` `image/jpeg`; `variant=thumb`
  returns the 128² variant. `Cache-Control` is long-lived/immutable.
- **No avatar → 404**: a pilot with no uploaded avatar returns 404 for that route
  (and the UI shows initials instead of a broken image).
- **Cache-bust**: the `v=` query param in the avatar URL reflects `avatarUpdatedAt`
  and changes after a new upload.

### Ingestion default visibility

**E2E scenario:**
- With default privacy set to **Public** in `/settings`, upload an IGC flight and
  confirm the resulting flight is **public** (visible on the public surface / shows a
  public badge). Then set default to **Private**, upload another, and confirm it is
  **private** (not publicly visible). Routes: `/settings`, `/upload`, `/logbook`.

## Regression Checks
- **App header** still renders the wordmark, Logbook / Upload / Profile / Settings
  nav, the avatar (now linking to `/settings`), and Sign out. **The standalone
  "Upload flight" button was removed** — confirm the **Upload** nav tab is the entry
  point and `/upload` still works.
- **Onboarding** handle step still works (handle validation was extracted to
  `lib/handle.ts` and shared) — a new user can claim a handle and reach `/logbook`.
- **Public profile** (`/@handle`) still lists the pilot's public flights and now
  shows their avatar (or initials).
- **Flight privacy** unchanged for existing flights — private flights remain
  inaccessible to other viewers (viewer-scoped repo).

## Environment Notes
- **Auth**: dev magic link is written to `/tmp/leaf-magic-link.txt` and logged to the
  server console (no real email). Use it to sign in as a test pilot.
- **Two pilots** needed for the duplicate-handle scenario.
- **Image fixtures**: a small JPEG and PNG for the cropper; a HEIC fixture is
  optional (assert the negative if unavailable).
- The cropper modal is a custom component (no library) — Playwright can drive it with
  `mouse.move`/`down`/`up` over the viewport and the range input for zoom; the circle
  is a visual guide only (the server squares whatever rect is sent).
- DB-backed integration coverage lives in `test/settings.integration.test.ts`
  (auto-skips without `DATABASE_URL`).
