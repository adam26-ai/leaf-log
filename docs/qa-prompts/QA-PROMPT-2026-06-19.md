# QA Validation Prompt — Leaf Log M1 (first pass)

## Summary
Leaf Log is a private-first flight logbook: a pilot signs in by email magic-link,
uploads an IGC flight, sees it parsed into a flight page (track map + barograph +
metrics + named site), and chooses what to share. This is the first QA pass — it
covers the whole Milestone-1 surface plus two follow-ups (owner-only delete,
4-char short flight URLs). The single most important property to validate is the
**privacy invariant**: a private flight (and its track data) must be invisible to
everyone except its owner.

## Changes Overview
- **Auth & onboarding** — passwordless email magic-link sign-in; first-time users
  claim an `@handle` + display name.
- **Upload → flight page** — drag-drop/file-pick `.igc`; server parses + derives
  metrics; flight page shows a MapLibre track, a Recharts barograph, metric tiles,
  and the detected takeoff site.
- **Logbook** — the pilot's own flights, reverse-chron, with a stats bar (airtime,
  flights, sites) and public/private badges.
- **Sharing & privacy** — flights are **private by default**; an owner toggle makes
  one public; public pilot profiles at `/@handle` show only public flights.
- **Delete** — owners can delete their own flight (two-step inline confirm).
- **Short flight URLs** — flight ids are 4-char `[a-z0-9]` (e.g. `/flights/fwdc`).

## Validation Scenarios

### Auth & Onboarding
**E2E:**
- New pilot sign-up: `/sign-in` → enter email → submit → lands on `/check-email`.
  Retrieve the dev magic link (see Environment Notes), open it → redirected to
  `/onboarding`. Claim a handle + display name → lands on `/logbook`. Route: `/sign-in`.
- Handle validation: reserved/short/invalid handles (`upload`, `ab`, `Has Space`) are
  rejected with a message; a taken handle is rejected; a valid one proceeds. Route: `/onboarding`.
- Returning user: visiting the magic link a second time (already onboarded) goes
  straight to `/logbook`, not `/onboarding`.
- Route protection: while logged out, visiting `/logbook`, `/upload`, `/onboarding`
  redirects to `/sign-in?next=...`.

### Upload & Flight Page
**E2E:**
- Happy path: from `/upload`, upload the sample IGC (Environment Notes). Redirects to
  `/flights/<id>`. Verify the metric tiles are present and non-empty: Airtime, Max
  altitude, Height gained, Best climb, Strongest sink, Track distance, Straight line.
  The header shows the named site **"Mussel Rock"** and a local-time takeoff–landing
  range. A track map and a barograph render.
- Bad inputs (friendly, no crash): uploading a non-`.igc` file → "Not an .igc file";
  an empty file → "Empty file"; a `.igc` with no valid fixes → the flight page shows a
  "We couldn't read this flight" state rather than crashing. Route: `/upload`.
- Duplicate upload: uploading the exact same file twice does not create a second
  flight (shows "Already uploaded" / stays at one flight in the logbook).
- Track endpoint: `GET /api/flights/<id>/track` returns JSON (line + baro) for a
  flight the viewer may see.

### Logbook & Stats
**E2E:**
- After one upload, `/logbook` lists the flight with its site, date, duration, and a
  **Private** badge. The stats bar reflects 1 flight and non-zero airtime.
- Empty state: a brand-new pilot's `/logbook` shows the "No flights yet" prompt.

### Sharing & Privacy  ← highest priority
**E2E:**
- Toggle share: as the owner on `/flights/<id>`, click **Share flight** → the control
  flips to "Shared publicly" / "Make private". The logbook badge becomes **Public**.
- Logged-out access to a **public** flight: in a fresh (no-cookie) context, `GET
  /flights/<publicId>` returns 200 and shows the metrics; `/api/flights/<publicId>/track`
  returns 200.
- Logged-out access to a **private** flight: `/flights/<privateId>` returns **404**, and
  `/api/flights/<privateId>/track` returns **404**. (The raw IGC is never exposed at all.)
- Authenticated **non-owner**: signed in as a different pilot, visiting another pilot's
  **private** flight URL → 404; it does not appear on their `/@handle`.
- Public profile: `/@handle` (e.g. `/@fleafrier`) lists only **public** flights and shows
  a stats bar computed from public flights only. A handle that doesn't exist → 404.
  A bare segment without the `@` (e.g. `/fleafrier`) → 404.

### Delete Flight
**E2E:**
- Owner deletes: on their own `/flights/<id>`, "Delete flight" → "Yes, delete" (two-step)
  → redirected to `/logbook`, and the flight is gone (its URL now 404s).
- No delete control for non-owners: a logged-out visitor (or a different signed-in pilot)
  viewing a **public** flight does NOT see a delete control.

### Short Flight URL IDs
**E2E:**
- After uploading, the resulting URL matches `/flights/[a-z0-9]{4}` (4 chars), not a long
  cuid. Two uploads produce two distinct short ids.

## Vitest scenarios (pure logic, no UI)
The app already ships unit tests; the QA agent may add adversarial cases:
- `parseIgc` in `lib/igc/parse.ts`: malformed/truncated/empty input never throws;
  UTC midnight rollover ordering; zero/stuck baro treated as absent.
- `deriveMetrics` in `lib/igc/derive.ts`: smoothed climb/sink within tolerance on a
  known synthetic flight; cumulative gain not inflated by 1 s jitter.
- `findSite` in `lib/sites/lookup.ts`: a known seeded coordinate (Mussel Rock) resolves;
  out-of-range coordinates return null; takeoff radius is tighter than landing.
- `generateShortId` / `createWithShortIdRetry` in `lib/short-id.ts`: 4-char `[a-z0-9]`,
  caller-supplied id wins, retries on an id collision, does NOT retry on the
  `(ownerId, igcSha256)` dedup constraint.

## Regression Checks
- `GET /api/health` returns `{ status: "ok", db: "up" }`.
- The landing page `/` and `/sign-in` render (200) while logged out.
- Branding sanity: the wordmark + amber accent bars render; no console errors on the
  flight page.

## Environment Notes
- **App:** http://localhost:3000 (Next.js dev). App repo: `~/code/leaf-log` (read-only
  for QA). Local Postgres via `pnpm db:up`; sites seeded via `pnpm db:seed`.
- **Magic-link in dev (critical for E2E auth):** no email is sent. After requesting a
  link at `/sign-in`, read the URL from **`/tmp/leaf-magic-link.txt`** (also printed to
  the server console) and navigate to it in the same browser context. Each request
  overwrites the file, so delete it before requesting to avoid a stale link.
- **Sample flight:** generate one with `node --import tsx scripts/gen-fixture.ts /tmp/sample.igc`
  (a synthetic Mussel Rock thermal+glide), or reuse `test/e2e/.fixture.igc`. Its takeoff
  is at Mussel Rock, CA, so the named-site lookup should label it "Mussel Rock".
- **Two-pilot privacy tests** need two accounts — sign up two emails (e.g.
  `a@test.local`, `b@test.local`); each gets its own magic link via the file above.
- A reference happy-path E2E already exists at `test/e2e/happy-path.spec.ts` in the app
  repo for the expected selectors/flow.
