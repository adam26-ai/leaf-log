# QA Validation Prompt — Geotagged Flight Photos + replay-timeline rework

## Summary
Two batches since the last pass: (1) **Geotagged Flight Photos** — owners upload photos
(JPEG/PNG/HEIC) that get pinned on the flight's track, shown in a lightbox gallery, and linked
to the replay timeline; and (2) a **shared replay-timeline interaction rework** with a 3D
chase camera and a terrain-anchor fix. All on the flight detail page `/flights/[id]`.

## Changes Overview
- **Photo upload** (owner-only): JPEG/PNG/HEIC, multi-file, downscaled + EXIF-stripped server-side.
- **Placement**: timestamp-first (EXIF capture time → UTC via the flight's offset → interpolate
  on the track), EXIF-GPS override. Un-placeable photos upload but stay **unpinned**.
- **Map pins** on the 2D map: hover shows the photo; clicking a pin (or a gallery thumbnail)
  **scrubs the replay** to that moment.
- **Lightbox gallery**: thumbnail grid → full image with prev/next + keyboard; owner can delete.
- **Privacy**: photos inherit the flight's visibility, served only via authorizing routes.
- **Replay rework (PR #9)**: removed the awkward map-hover cursor; one shared play scrubber drives
  both 2D and 3D and is remembered across the 2D↔3D switch; selection persists until you click a
  map; a 3D **Camera: Follow / Fixed** toggle; and a fix so 3D tracks sit on the terrain (not buried).

## Validation Scenarios

### Photo upload & gallery
**E2E (Route: `/flights/[id]`, signed-in OWNER):**
- Owner sees an **"Add photos"** control; uploading 1+ JPEGs adds thumbnails to a **Photos** gallery.
- Uploading a **HEIC** file works end-to-end (the thumbnail decodes and renders) — iPhone default
  format. Use a tiled HEIC; `test/photos/fixtures/tiled-sample.heic` is one.
- Uploading a **non-image** (e.g. `.txt`) or a wildly large file is rejected per-file with a message,
  without failing the rest of the batch.
- Re-uploading the **same file** is a no-op (deduped) — count doesn't double.
- **Lightbox**: clicking a thumbnail opens the full image; `←`/`→` and the arrows navigate; `Esc`
  closes; the OWNER sees a **Delete** action; deleting removes it from the gallery.
- A **non-owner** viewing a public flight sees the gallery but **no** Add-photos/Delete controls.

### Photo placement & map pins
**E2E (2D "Map" mode):**
- A photo whose capture time falls **within the flight window** shows a **pin on the track**;
  hovering the pin shows a thumbnail preview; clicking the pin **moves the replay scrubber** to
  that time. (See Environment Notes — placement needs the time to land in `[takeoff, landing]`.)
- A photo with **no usable time / GPS** or taken **outside the window** still appears in the gallery
  but is **unpinned** (owner sees an "unpinned" marker) and has **no** map pin.

### Photo privacy & serving (security-critical)
**E2E / HTTP:**
- For a **PRIVATE** flight owned by someone else (or anonymous): `GET /api/flights/[id]/photos`
  and `GET /api/flights/[id]/photos/[photoId]?variant=thumb|display` both return **404**.
- For a **PUBLIC** flight: those routes return the list / image to anyone.
- A photo id from flight A requested via flight B's route → **404** (flight/photo mismatch).
- **Upload/delete are owner-only**: a non-owner `POST`/`DELETE` to those routes → 404.
- **Served image bytes carry no EXIF** — fetch a served `display` image and confirm no
  `DateTimeOriginal`/GPS (the originals do have them).

**Vitest (pure logic, already covered — extend edge cases):**
- `placePhoto` in `lib/photos/placement.ts`: in/out-of-window, GPS-in/out-of-bounds, null flight
  offset → unpinned (never clamped).
- `localToUtcMs` / `parseExifDateTime` / `parseExifOffset` in `lib/photos/time.ts`: ±/0 offsets,
  missing `OffsetTimeOriginal`, DST/boundary times.

### Replay timeline & 3D camera (PR #9)
**E2E (Route: `/flights/[id]`):**
- **Map hover does nothing** to the cursor now; the cursor comes only from **barograph hover** and
  the **play scrubber**.
- One **shared scrubber** drives both 2D and 3D; its position is **remembered** when you switch
  Map↔3D replay.
- Leaving the hover/scrubber **keeps** the highlight; **clicking a map clears** it.
- **3D**: a **Camera: Follow / Fixed** toggle (persists across reload via localStorage). With Follow
  on, playing the replay keeps the glider locked in place while terrain moves under it.
  (3D rendering is WebGL — see Environment Notes; assert structure: the toggle flips, the slider
  advances during Play, no console errors. Pixel-level checks need a real GPU.)

## Regression Checks
- The existing flight page still shows metrics, the 2D map + barograph, basemap switcher, the
  linked barograph cursor, share toggle, and owner delete.
- **Terrain anchor:** in 3D, the flight path renders on/above the terrain (not sunk into it) — best
  on a real GPU; at minimum the 3D `<canvas>` renders with no console errors.
- Existing privacy invariant still holds for the **flight** itself (private → 404 for non-owner on
  the page and `/api/flights/[id]/track` + `/replay`).
- Upload of an IGC, parse/derive, and the logbook list are unaffected.

## Environment Notes
- **Photos require PR #12 merged** (the routes/UI). PR #10/#11 (schema + lib) are already on `main`.
- **Auth (dev magic-link):** request at `/sign-in`, read the URL from `/tmp/leaf-magic-link.txt`
  (delete first to avoid a stale link).
- **To get a PINNED photo**, the photo's EXIF `DateTimeOriginal` (local, no zone) must fall inside
  the flight window after bridging via the flight's `localUtcOffsetMinutes`. The fixture
  `test/photos/fixtures/exif-sample.jpg` is `2026-06-19 13:12:11` local (UTC-7) → 20:12:11Z, with no
  GPS; pair it with a flight spanning that instant, or it uploads unpinned. `tiled-sample.heic`
  exercises the HEIC path.
- **HEIC at runtime:** decoded by `heic-convert` (libheif-wasm) in the **nodejs** route runtime. Note
  for any Vitest the QA writes: `heic-convert` and `exifr` break under the default **jsdom** env —
  use `// @vitest-environment node`.
- **WebGL (3D):** software GL (`--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader`);
  terrain/imagery don't render meaningfully headless — assert structure, not pixels.
- **Limits:** JPEG/PNG/HEIC only; ≤25 MB input; ≤10 files/batch; ≤40 photos/flight; display ≤2048px,
  thumb ≤420px.
