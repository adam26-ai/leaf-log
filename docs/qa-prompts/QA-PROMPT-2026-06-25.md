# QA Validation Prompt — Geotagged Photos (live) + pin interactions

## Summary
The Geotagged Flight Photos feature is now fully merged (PR #12 + #13). Owners upload photos
that get pinned on the flight track (2D map AND 3D replay) as camera icons; hovering a pin scrubs
the replay and previews the photo, clicking opens a lightbox. This pass focuses on the now-live
upload + the pin/gallery interactions (the prior 2026-06-24 prompt described the data/privacy
design before the UI shipped).

## Changes Overview
- **Upload** (owner-only): **drag-and-drop or click**, multi-file, JPEG/PNG/**HEIC**.
- **Camera-icon pins** (not dots) on the **2D map** and the **3D replay**, placed where each photo
  was taken (3D pins sit at the track's altitude).
- **Pin interactions**: hover → the shared scrubber jumps to that moment (player slider + barograph
  + map cursor) and a **thumbnail preview** shows; click → **lightbox**. In **3D**, hovering a pin
  does **not** recenter the camera (so the icon stays under the cursor).
- **Gallery**: thumbnail grid + lightbox (prev/next, keyboard, owner delete). **Unpinned** photos
  appear with an "unpinned" tag and a reason (hover tooltip + lightbox caption).
- **Instrument overlay**: a dark glass panel (Time / Altitude / Vario / Speed) overlaid on the map,
  appears when a point is selected.

## Validation Scenarios

### Upload (Route: `/flights/[id]`, signed-in OWNER)
**E2E:**
- The "Add photos" control is a **dropzone**: dropping image files uploads them; clicking it also
  opens a file picker. Both paths add thumbnails to the **Photos** gallery.
- A **HEIC** file uploads and its thumbnail renders (decoded server-side).
- A non-image (e.g. `.txt`) is rejected per-file with a message; the rest of a batch still uploads.
- Re-uploading the same file is a no-op (deduped — count doesn't grow).
- Non-owners (public flight) see the gallery but **no** Add-photos/Delete controls.

### Pins + interactions (2D map)
**E2E:**
- A photo whose capture time lands in the flight window shows a **camera icon** on the track.
- **Hovering** the icon: the playback slider + the barograph cursor jump to the photo's time, and a
  **thumbnail preview** appears; the amber scrubber dot renders **on top of** the camera icon.
- **Clicking** the icon opens the **lightbox** (and scrubs to that moment).
- Clicking empty map clears the selection (overlay/cursor hide).

### Pins + interactions (3D replay)
**E2E (WebGL — see Environment Notes):**
- Camera icons render **on the 3D track at altitude**.
- **Hovering** a pin scrubs the replay (the sphere jumps to that point) and shows a thumbnail, and
  importantly **does not recenter/jump the camera** (regression guard for the awkward
  hover→recenter→lose-hover loop).
- **Clicking** a pin opens the lightbox.
- Note: deck.gl **hover** picking may not fire under headless software-GL (click does) — verify
  hover on a real GPU; assert structure where hover can't be triggered.

### Gallery & lightbox
**E2E:**
- Thumbnail grid below the map; clicking a thumbnail opens the lightbox and scrubs the replay.
- Lightbox: `←/→` + arrow buttons navigate, `Esc` closes, owner sees **Delete** (removing it drops
  it from the gallery and 404s its image route).
- **Unpinned** photo: shows in the gallery with an "unpinned" tag; the reason is in the thumbnail
  tooltip and a lightbox caption (e.g. "Taken outside this flight's time").

### Instrument overlay
- A dark panel (Time / Altitude / Vario / Speed; vario green=climb / red=sink) overlays the map
  when a point is selected (hover/scrub/play) and disappears when nothing is selected; it never
  blocks map pan/zoom.

## Regression Checks
- **Privacy (security-critical, unchanged)**: a private flight's photos return **404** to
  anonymous + non-owner on both the list (`/api/flights/[id]/photos`) and serve
  (`/api/flights/[id]/photos/[photoId]?variant=thumb|display`) routes; public-flight photos are
  visible to anyone; a photo id can't be fetched via the wrong flight; served bytes carry **no
  EXIF**.
- Existing flight viz still works: 2D/3D toggle, basemap switcher, barograph, shared scrubber +
  playback, 3D camera Follow/Fixed toggle, terrain anchoring.
- IGC upload / parse / logbook list unaffected.

## Environment Notes
- App at http://localhost:3000. **Auth (dev magic-link):** request at `/sign-in`, read the URL from
  `/tmp/leaf-magic-link.txt` (delete first to avoid a stale link).
- **To get a PINNED photo**, the photo's EXIF `DateTimeOriginal` (local, no zone) must fall in the
  flight window after bridging via the flight's `localUtcOffsetMinutes`. Fixtures:
  `test/photos/fixtures/exif-sample.jpg` (2026-06-19 13:12:11 local UTC-7, no GPS) and
  `test/photos/fixtures/tiled-sample.heic` (exercises HEIC). To pin one, pair it with a flight whose
  window contains that instant, or insert a `Photo` row with `lat/lon/tSec` directly.
- **WebGL/3D**: software GL (`--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader`);
  terrain/imagery don't render meaningfully headless, and **deck.gl hover picking doesn't fire**
  there (click does) — assert structure, verify hover on a real GPU.
- **Vitest**: `exifr` / `heic-convert` need `// @vitest-environment node` (jsdom breaks them).
- Caps: JPEG/PNG/HEIC only; ≤25 MB; ≤10/batch; ≤40/flight.
