# QA Validation Prompt — Flight-page enhancements (hover/instruments/basemaps/3D)

## Summary
A batch of upgrades to the flight detail page: the 2D map and 3D terrain replay
now share a linked hover cursor, a live instrument readout, selectable basemaps
(incl. satellite), a 3D glider that follows the camera and persists where you
scrub, and a compact one-row metric header. The 3D track also sits correctly on
the terrain now. Everything lives on `/flights/[id]`.

## Changes Overview
- **Linked hover** — hovering the barograph highlights the matching spot on the map; hovering the map track highlights the barograph point. Bidirectional, 2D + 3D.
- **Live instrument readout** — a Time / Altitude / Vario / Speed panel above the map for the point under the cursor; in 3D it follows the replay (play/scrub/hover).
- **Selectable basemaps** — a "Basemap" dropdown (Map / Satellite / Hybrid / Topo / Streets) that applies to both the 2D map and the 3D replay; persists across reloads.
- **3D replay UX** — the scrubber/clock follow a barograph hover; releasing a scrub leaves the glider where it was (Play resumes from there); the glider is a 3D sphere; the camera follows the glider while scrubbing/playing.
- **3D altitude fix** — the flight path now sits on/above the terrain (no longer dives through mountains).
- **Compact header** — the 7 summary metrics now sit on a single horizontal row.

## Validation Scenarios

### Compact summary header
**E2E (Route: `/flights/[id]`, a READY public flight):**
- The summary metrics (Airtime, Max altitude, Height gained, Best climb, Strongest sink, Track distance, Straight line) render on **one horizontal row** in a single card. On a narrow viewport the row scrolls horizontally rather than wrapping into the page height.

### Linked hover (2D)
**E2E (2D "Map" mode):**
- Hovering the **barograph** shows a vertical reference line on it AND a small amber **cursor dot appears on the map track** at the matching position. Moving along the barograph moves the dot.
- Hovering the **map track** highlights the matching point on the barograph (a reference line appears). Moving the mouse off the track clears it.

### Live instrument readout
**E2E:**
- A readout strip above the map shows **Time / Altitude / Vario / Speed**. With no hover it shows a hint ("Hover the profile or map…").
- On **barograph hover** the four values populate and update as you move; **Vario is coloured green when climbing and red when sinking**.
- In **3D mode while the replay plays**, the readout updates live (the Time advances). Note: Vario/Speed are derived; assert they're present + numeric, not exact values.

### Selectable basemaps
**E2E:**
- The **Basemap** dropdown changes the map style in **both** 2D and 3D, and the **amber track stays drawn** after switching (it's re-added after the style swap). Switch Map → Streets → back; the track persists each time.
- The choice **persists across a page reload** (localStorage).
- **Key-gating:** Satellite/Hybrid/Topo use MapTiler. If `NEXT_PUBLIC_MAPTILER_KEY` is set in the env, those options are selectable and load imagery; if not, they're **disabled** in the dropdown (labelled "needs key") while Map/Streets still work. Test whichever matches your env (see Environment Notes).

### 3D replay interaction
**E2E (3D "3D replay" mode; WebGL — see Environment Notes):**
- **Play** advances the time slider + clock; **Pause** stops it; the slider loops at the end; speed buttons (4/8/16/32×) toggle.
- **Scrubber follows hover:** hovering the barograph moves the 3D slider/clock to the hovered time (not just the glider).
- **Scrub persists:** hover to scrub to ~70%, then move the mouse away — the slider/glider **stay** at ~70% (don't snap to 0); pressing **Play** resumes from there.
- A `<canvas>` renders; the glider marker and track are present. Don't assert terrain/imagery pixels under software GL.

## Regression Checks
- **3D track on terrain:** the flight path renders on/above the terrain, not buried inside it (best checked visually on a real GPU; at minimum the 3D `<canvas>` renders without console errors).
- The flight page still shows the named site/header, the map track + barograph, the share toggle, and the owner-only delete control.
- **Privacy unchanged:** a private flight (and `/api/flights/[id]/track` and `/api/flights/[id]/replay`) still 404 for anonymous + non-owner; public flights 200. (Carried from earlier passes — smoke only.)
- **Favicon:** the page `<head>` references `/icon.svg`, `/favicon.ico`, `/apple-icon.png` (all 200).

## Vitest scenarios (pure logic)
- `instrumentAt` in `lib/flights/instruments.ts`: from a replay path it interpolates altitude/vario/ground-speed/time/position — vario positive mid-climb, negative mid-glide, times clamped to range, null for an empty path.
- `buildReplayPath` in `lib/igc/replay.ts`: aligned `[lon,lat,alt,t]`, monotonic time, sample cap (already covered — extend if useful).

## Environment Notes
- **App:** http://localhost:3000. Repo `~/code/leaf-log` (read-only for QA).
- **WebGL (3D):** launch Chromium with software GL — `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader`. Terrain/imagery don't render meaningfully headless; assert structure (canvas, controls, readout, endpoints), not pixels.
- **MapTiler key:** for Satellite/Hybrid/Topo, `NEXT_PUBLIC_MAPTILER_KEY` must be in the dev env (it's in `.env.local`). Without it those options are disabled by design — test the disabled-state path instead.
- **Auth (dev magic-link):** request a link at `/sign-in`, then read the URL from `/tmp/leaf-magic-link.txt` (delete before requesting to avoid a stale link). Needed for owner/non-owner privacy cases.
- **A flight with a track** is required. Generate one with `node --import tsx scripts/gen-fixture.ts /tmp/sample.igc` (a synthetic Mussel Rock flight) and upload it; for an alpine flight (better terrain/vario), any real `.igc` works. Make one public for anonymous E2E.
